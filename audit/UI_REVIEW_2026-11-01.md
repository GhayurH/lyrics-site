# UI, accessibility, and codebase audit — 1 November 2026

**Baseline:** `main` at `d4b3cfe0334b`. **Branch:** `audit/ui-consistency-refactor-2026-11-01` (PR #33). This review covers the shared Astro reader architecture, CSS ownership and cascade, responsive mode transitions, browser controllers, public copy, documentation, and automated tests. It is based on source/markup inspection and Playwright CI, **not** a hands-on physical-device or Cloud Browser inspection.

## Findings and implemented corrections

| Priority | Finding | Implemented resolution |
| --- | --- | --- |
| High | Page-by-page Basta, continuous Basta, and standalone lyrics each declared overlapping edition-grid rules; a portrait-only override disagreed with narrow landscape and desktop windows. | Centralized edition tracks, scan/text rows, and single-language placement in `reading-columns.css`; page and Focus stacking follow the 46rem reader-container boundary, including centred bilingual Focus columns. Removed superseded route defaults and the competing 760px override. |
| High | Image and text sometimes shared a row on narrow/rotated screens, and a portrait shortcut in the scan controller could disagree with actual layout. | Focus stacks scans above poetry at the shared boundary; floating scans now depend on physical adjacent-panel geometry, not device orientation. |
| High | Basta page progress used the document even when Focus Mode scrolled a fixed reader. Restoring a saved Focus position also targeted the document. | Both save **and restore** use the active scroll container. The temporary `resume` query is removed after applying it, preventing stale reload jumps. |
| High | Focus Escape closed the whole reader while Options were open; Contents and Options could overlap and leave focus on a hidden control. | Escape first dismisses Options; opening Contents closes Options. Closing Contents returns keyboard focus to a visible toolbar control. |
| High | Retracting the site header set `visibility:hidden`, removing navigation controls from keyboard navigation. | The header retracts by transform alone, stays keyboard-reachable, and is restored on `focusin`. |
| Medium | Standalone single-language sizing, Basta landing declarations, global button outlines, and obsolete hero/category/cover selectors had duplicate or dead definitions. | Consolidated component defaults and theme tokens; removed unused selectors and `lyric-reading-grid-single` special state. |
| Medium | Site navigation and reader defaults encoded separate copies of the 700px JavaScript boundary; scroll-to-top ignored reduced motion. | Shared the viewport query in `client/viewport.ts` and honor `prefers-reduced-motion`. |
| Medium | Home, search, and Basta meta descriptions used technical count/OCR jargon rather than visitor language. | Simplified descriptions and standardized edition terminology. |
| Medium | Recitation step navigation could lose its active marker during smooth scrolling, because intermediate section intersections overrode a clicked step. | Explicit step selection takes priority until the visitor scrolls manually; automatic intersection tracking resumes afterward. |

## Code ownership and maintainability

- **Keep:** Astro-generated, progressively enhanced reading pages; canonical parsers in `src/lib/`; shared `ReadingControls.astro`; stable Recitation Set IDs; Pagefind; native source-scan links; isolated Cloudflare Pages Functions and D1 permissions.
- **CSS boundaries:** `tokens.css` defines design constants; `core.css` defines shared primitives; `reading-columns.css` owns edition tracks, scan placement, and responsive reader geometry; `reading-focus.css` owns immersive shell; route CSS owns local presentation and index-specific layouts. Treat container-width changes as cross-reader changes, not per-route patches.
- **Controllers:** `reader-state.ts` owns edition preferences; `reading-focus.ts` owns history, overlays, and Focus position; `floating-scans.ts` detects physically parallel scans; `reading-progress.ts` owns resume behavior; `synced-columns.ts` manages taller text-panel scrolling. Avoid creating parallel responsive authorities.
- **Future optional extractions:** `reading-columns.css` still combines reader layouts with toolbar and index presentation; `recitation-builder.ts` and `recitation-reader.ts` are sizable orchestration modules. Split only when boundaries are genuinely independent and ordering/interaction tests protect the behavior. Not every repeated selector is dead: state, container, and accessibility overrides often need distinct specificity.
- **Docs:** README is the short project entry point. Architecture, Contributing, Assets, Recitation Sets, and Operations have separate ownership. Do not copy editorial procedures into the public About page.

## Automated verification

The project runs Node unit tests, stable recitation-ID checks, Astro/Pagefind build, Basta boundary audit, asset-routing checks, and a complete Chromium browser regression suite for `[full-ci]` commits. The tests exercise selected editions, mobile/desktop geometry, scroll state, keyboard Focus behavior, fonts/themes, recitation journeys, and no-JavaScript content. The PR's latest successful GitHub Actions run is the source of truth for merge readiness; after each new commit, verify that **that commit** passed.

Source poetry, Recitation IDs, R2 assets, and Cloudflare D1 schema/permissions were intentionally not changed by this UI audit.
