## Maintainability assessment

**Preserve:** Astro static rendering with progressive enhancement; canonical parsing in `src/lib/`; shared `ReadingControls.astro`, edition state, theme/font allowlists, design tokens, and source IDs. R2-backed scans have useful native-link fallbacks. Long-lived recitation programme formats and organizer authorization must remain stable.

**Candidate future extractions:** `reading-columns.css` (~590 lines) interleaves edition grids, toolbar/navigation UI, scans, and index styles; `basta.css` (~670 lines) covers multiple concerns; `recitation-builder.ts` and `recitation-reader.ts` are substantial controllers. Split by responsibility only with import-order and functional regression tests. Repeated selectors inside container/media queries are usually intentional, and `!important` may protect native hidden states or image-only fallbacks; do not blindly delete them. Comments explaining non-obvious behavior are useful, whereas historical patch notes should be replaced with present-tense invariants.

**Documentation:** README is already a short entry point; Architecture, Contributing, Assets, and Recitation Sets each own distinct rules. Keep technical audits here instead of adding internal details to the public About page or bloating README.

## Acceptance / follow-up verification

- Run `npm run build`, `npm run test:browser`, and a visual comparison of 320×568, 390×844, 640×360, 700×800, 768×1024, 1050×900, 1440×900 plus browser zoom.
- Check regular/Focus and individual/bilingual/image combinations on standalone lyrics, page-by-page/continuous Basta, and mixed-content recitation sets. Inspect overlaps, content widths, scroll and exit position, verse clipping, sticky scans, and options controls.
- Audit keyboard tab order, readable focus, menu dismissal, image viewer, reduced motion, theme contrast, RTL labels, and no-JS paths. WCAG 2.2 reflow/focus-not-obscured guidance is the benchmark; one-line poetry must be tested at narrow effective widths rather than assumed accessible.
- After verifying the above, consider extracting independent toolbar/scan/index CSS and dividing long browser suites by behavior, not by device. Check event listener lifecycle, page-data loading, and publication security separately.

**Limitations:** Changes are a first implementation, not a claim that all combinations or every non-UI file has been runtime-tested. Passing browser CI does not replace hands-on screenshots and accessibility review.
